Gateway repair

Haelo

A small OpenAI-compatible proxy that sits between a verification engine and any OpenAI-compatible gateway. The engine does not change — it talks to the proxy exactly as it would talk to the gateway. This is the layer that turned a mostly-failing evaluation into a mostly-passing one, and it is the operator's own work.

What it actually does

  • Caps thinking per request and fits each request to the model's real context window — the failure that cost the uncapped run an answer entirely.
  • Repairs a schema-invalid answer by re-sending the failed turn as a continuation carrying the validation errors, rather than restarting.
  • Keeps a long call alive past the client's silence timeout, and runs the engine's own hard checks before answering.
  • Layer-zero control strings per model — r-bare, clamp-full, lift=N, salvage, chk-gate — measured per gateway, not guessed.

On the same gateway, the bare engine took 8 of 9 designs through plan and coverage; with Haelo in front of it, 9 of 9. The proxy changed no engine code. It changed the request.

What the delivery is

  • The engine is a dependency, not a claim. UVMStack is Trishna Raj's work — measured at — LOC, credited to its author, and evaluated here rather than presented as the operator's own.
  • What was added around it: an Electron and React front end with fourteen feature domains, an OpenAI-compatible gateway provider, a licence gate that refuses to run an unlicensed build, and a five-layer settings resolution where a project may tune a model but may not redirect where requests go.
  • The day-one probe asks a gateway twelve short questions — does it honour a thinking budget, will it continue a cut-off answer, is it repeatable at temperature zero — and reports the answers before anything else is attempted.

Measurement harness

Oden Flow

The runtime that decides whether a model can actually do the job. A frozen benchmark tree, a SHA-256 manifest checked before every stage, and a gate loop that will not let a model skip a step.

The rules it enforces

  • Nothing is patched. The engine and the benchmark tree are deployed verbatim. A SHA-256 manifest is taken at deploy time and verified before every stage; a difference is a refusal, not a warning.
  • Same items, same conditions. One canonical order frozen for the whole campaign, lockstep blocks of ten, identical prompts, temperature 0, and context-exceeded counted as an attempted failure so the denominator never shifts.
  • Stop at the first bad step. A failed step ends that model's round — the remainder will not build on a bad base. Steps that passed are kept and never redone.
  • Infrastructure failures are not model failures. Calls the adapter marked as infrastructure faults are re-run rather than charged to the model.

Local inference

Colibri

An inference server written from the ground up in C, with CUDA, Metal and Vulkan backends behind one interface — so the models that judge the engine can run on the machine next to it, on the same silicon, with nothing phoning home.

Why it exists

  • The evaluation harness needs a model it controls end to end: same build, same quantisation, same context length, no API in the loop. A measured result is worth nothing if the serving stack is a moving target.
  • One core, three backends — CUDA for the discrete workstation GPU, Metal for the laptop, Vulkan for the card that has no CUDA path at all.
  • It reports its own internals: a per-turn breakdown of attention, expert matmul, expert disk and head time, which is what makes prefill-versus-decode a measurement rather than a guess.

Oden IDE

The web IDE the engine runs inside: sixteen domains of server modules, a per-area permission model, and an agent shell that executes inside a bubblewrap sandbox with secrets masked and protected paths read-only. — development files, — packaged.

One password, server-side sessions, a CSRF token per session, a same-origin check on every change, and an audit log of every change. Five wrong passwords lock the client address for thirty seconds, and each further one doubles it.

Verification methods

Method

The constraints that produced the work, stated as constraints.

Nothing on this page is typed

Every figure is produced by a script that walks the real trees — or, for the second machine, the file index its backup keeps — and writes the result to a manifest the page reads at load. The number and the artefact cannot disagree, because one produces the other.

One append-only decision log

2,683 entries recording what was decided, why, and who signed it off — from the rule that the benchmark tree is never patched, to the measurement that thread count was costing one model 97% of its throughput. It is the closest thing here to a primary source.

Negative results are results

A thermoelectric geometry that does not pay. A benchmark board that was invalid. A model that does not repeat at temperature zero. Each is reported with the same weight as the wins, because a page that only shows wins is not a measurement.

Review in writing, separately

Critique documents written by a separate reviewer, verdicts issued as DONE / PARTLY / NOT DONE, and the fixes applied in the open. Two design reviews here each end with a full second document written against the first.

Licence hygiene

SPDX allow-lists on training data and dependencies, explicit exclusions for non-commercial and copyleft corpora, notices shipped with every bundle, and self-hosted fonts so the page makes no third-party request.

Two machines, one record

Origo is the desktop: an RTX 4080 SUPER, the source trees, the instruments. Oden is a KVM guest with the GPU passed through, and it is where the benchmarks ran. Both are backed up to Proton Drive with content-defined deduplication, and this page reads the file index of that backup.
